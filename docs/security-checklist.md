# HTTP security checklist

Every HTTP surface of Tracekit passes this checklist. Each item names the tests that enforce it;
`tests/test_security_checklist.py` fails when a handler is added without being listed below and probed, or when a test
named here no longer exists.

## Surfaces

| Handler | Serves | Kind |
|---|---|---|
| `tracekit/observe.py:Handler` | `tracekit view` (v2 store, or with `view.logs` every log of a central deployment at `/runs`, `/api/runs`, `/api/run` and `/api/bundle`; token, or OIDC login at `/login` and `/callback`; an approver's approval pages at `/approvals`; with why logs, `tracekit view --why` and `tracekit why serve`, the why read API `/api/why/workspace` and `/api/why/runs/<id>` for the token only, the replay POSTs `/api/why/runs/<id>/tests` and `/api/why/runs/<id>/attribute`, and `POST /v1/ingest` for a bearer token only: an `--ingest-token`, which reads nothing, else the token) and `tracekit observe` or `tracekit view --ledger`/`--bundle` (v0.2 ledger) | browser; read-only but for the approval pages and the why replay POSTs; ingest API |
| `tracekit/transport/http.py:_Handler` | signer `POST /v2/rpc` and OTLP/HTTP `POST /v1/traces`; `tracekit issuer serve` | API |
| `tracekit/gateway.py:_Handler` | `tracekit gateway serve` (LLM gateway) | API |
| `tracekit/executor.py:_Executor` | `tracekit executor serve` (`GET /v1/actions`, `POST /v1/actions/<name>`: actions run with credentials the agent never holds) | API |
| `tracekit/mcp_gateway.py:_McpGateway` | `tracekit mcp-gateway serve` (`POST /mcp`: MCP over streamable HTTP to the configured upstream servers) | API |
| `tracekit/a2a_gateway.py:_A2aGateway` | `tracekit a2a-gateway serve`, experimental (`POST /a2a/<upstream>`: A2A JSON-RPC `message/send`, `message/stream` and `tasks/get` to the configured A2A servers; any other method refused) | API |
| `tracekit/egress.py:_Handler` | `tracekit egress serve` (egress observer: `CONNECT host:port` and absolute-form `http://` requests, forwarded to the outside; no TLS interception) | API, proxy |
| `tracekit/signer/metrics.py:Handler` | signer `/metrics`, `/logs/v0` and tlog tiles | API, public data |
| `tracekit/otlp.py:H` | `tracekit otel serve` (loopback OTLP receiver) | API |
| `tracekit/ingest.py:H` | `tracekit ingest serve` (remote ingest) | API |
| `tracekit/witness_server.py:H` | `tracekit witness serve` | API |
| `tracekit/public_witness_server.py:H` | `tracekit public-witness serve` (C2SP tlog-witness `add-checkpoint`, open `register`, aggregate `stats`) | API, open: a log proves its key by signing; limits per address and origin |
| `tracekit/proxy.py:Handler` | `tracekit-proxy` (Anthropic proxy) | API |
| `tracekit/slack_approvals.py:Handler` | `tracekit approvals slack serve` (Slack interactivity callbacks) | API, Slack-signed |

The browser surface is the only one that serves HTML or holds a session. The viewer's approval pages and its why
replay POSTs (which run allow-listed programs and add test results to a run) are the only requests a session can
change state with; the why logs are the token's only (an OIDC session gets 403: they belong to no tenant), and their
ingest endpoint takes the bearer token only, never the cookie. API surfaces authenticate every request by
header or client certificate (bearer token, mTLS, Kubernetes service-account or OIDC token, run token) and never read a
cookie, so a browser cannot ride a session on them. The public witness is open by design: it takes no credential, and
a log registers by signing a checkpoint with the key it registers (one key per origin, the first). The Slack bridge authenticates each callback by Slack's v0 request
signature instead, and answers approvals only through the signer as the Slack user who clicked.

## Adding a surface

Add the handler to `SURFACES` and `Surfaces.PROBES` in `tests/test_security_checklist.py` and to the Surfaces table
above, and make it pass every item that applies to its kind.
